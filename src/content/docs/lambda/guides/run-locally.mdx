The image is built on the [AWS Lambda .NET base image](https://gallery.ecr.aws/lambda/dotnet), which includes the Lambda runtime interface emulator. Your function runs locally exactly the way Lambda runs it, just with fewer invoices.

## Build and run

<Tabs syncKey="runner">
  <TabItem label="Docker Compose">
    ```bash
    docker compose up -d --build
    ```

    Compose builds the `run` stage, publishes port 8750, turns on sample data, and starts an OpenTelemetry Collector and the Aspire dashboard next to it. Shut it down with `docker compose down`.
  </TabItem>
  <TabItem label="Docker">
    ```bash
    docker build . --target run --tag acme-reviews:local
    docker run --rm -p 8750:8080 -e Database__SeedSampleData=true acme-reviews:local
    ```
  </TabItem>
</Tabs>

Then invoke it from another terminal:

```bash
curl -X POST "http://localhost:8750/2015-03-31/functions/function/invocations" -d '{"limit":5}'
```

## See the telemetry

With Docker Compose, the function sends its traces, metrics and logs over OTLP to an [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/), which forwards them to the [Aspire dashboard](https://learn.microsoft.com/dotnet/aspire/fundamentals/dashboard/standalone) at [http://localhost:8752](http://localhost:8752). Each invocation is one trace: the function's span from the OpenTelemetry Lambda wrapper, with the use case under it. Traces and metrics are flushed before the function returns, so they're there by the time `curl` is. The logs still go to the console too, so `docker compose logs function` works as it always did. The dashboard has no login, and the collector accepts OTLP from anyone on ports 4317 and 4318. That's on purpose, so there's nothing to sign in to on your machine, and it's why the compose file is for your machine only. Don't run it anywhere other people can reach.

Run the image on its own and nothing is exported, because `OTEL_EXPORTER_OTLP_ENDPOINT` isn't set. Set it to send the telemetry to a collector of your own.

## Try the other functions

The image runs `GetMovies` by default. The same image also has `GetAuthors` and `GetReviews`. Pass the function's full handler name to `docker run` to start a different one.

```bash
docker run --rm -p 8750:8080 -e Database__SeedSampleData=true acme-reviews:local \
  "Presentation::WorksOnMyMachine.Reviews.Presentation.LambdaFunction.Handler_GetReviews_Generated::GetReviews"

curl -X POST "http://localhost:8750/2015-03-31/functions/function/invocations" \
  -d '{"movieId":"cb188ef6-14e7-f85f-2f78-924c2ab26b28","limit":2}'
```

The sample data uses a fixed seed, so that movie id is the same on every machine. See the [function reference](../../reference/functions/) for every request and response.

## Run the tests

```bash
dotnet test
```

Each test builds its own in-memory SQLite database from the migrations and the same fixed seed. No test can change what another one sees, and nothing touches the database file in `/tmp`.

## Run just one part of the Dockerfile

The `Dockerfile` has a stage for each job, so you can build only what you need.

| Stage | What it does |
| --- | --- |
| `build` | Restores and builds the solution |
| `test` | Runs every test with coverage |
| `coverage` | Exports the coverage report to your machine |
| `publish` | Publishes the Presentation project |
| `run` | The Lambda image you deploy |

```bash
docker build . --target coverage --output type=local,dest=out
```

## Stamp a version

```bash
docker build . --target run --tag acme-reviews:latest \
  --build-arg VERSION_PREFIX=1.2.3 --build-arg VERSION_SUFFIX=beta
```

<Aside type="tip" title="Stuck?">
  If `curl` hangs, the container is probably still applying migrations. Give it a second. If it says connection refused, check that port 8750 isn't busy with something else you forgot about.
</Aside>
