Sooner or later you'll want to evict *Deep Space Gardeners* and move your own domain in. The tempting move is to delete `Movies`, `Authors` and `Reviews` first. Don't. Half the tests stop compiling, and the shared plumbing (paging, validation, logging, the serializer and telemetry) suddenly has nothing to exercise it, so coverage falls through the floor.

Go the other way round. Build your first slice beside the sample domain, prove it works end to end, then take the movies out. This guide adds cinemas, with a `GetCinemas` function to list and search them and a `CreateCinema` function to add one, each with an API Gateway twin at `GET /cinemas` and `POST /cinemas`, and finishes with a solution that has no movies left in it. We ran every step on a fresh solution: it ends with 75 passing tests and 99.7% line coverage.

<Aside type="tip" title="Let Jacques do the typing">
  Each step names the skill in `.agents/skills/` that covers it. Point your coding agent at this page and your own domain, and it follows the same recipe.
</Aside>

The code below assumes you named the solution `WorksOnMyMachine.Movies`. Swap in your own name wherever you see it.

   ```csharp title="src/Infrastructure/Databases/MovieReviews/Configuration/CinemaConfiguration.cs"
   using Microsoft.EntityFrameworkCore.Metadata.Builders;
   using Models;
   ```

   Then wire it in:

   - **`MovieReviewsDbContext.cs`:** add `public DbSet<Cinema> Cinemas => this.Set<Cinema>();` beside the other sets.
   - **`Mapping/MovieReviewsMapper.cs`:** add `using AppCinema = Application.Cinemas.Entities.Cinema;` and `using InfraCinema = Models.Cinema;` with the other aliases, and this method:

     ```csharp
     [MapperIgnoreSource(nameof(InfraCinema.DateCreated))]
     [MapperIgnoreSource(nameof(InfraCinema.DateModified))]
     public partial AppCinema ToDomain(InfraCinema cinema);
     ```

   - **`EntityFrameworkMovieReviewsRepository.cs`:** add `using Application.Cinemas;` and `using ApplicationCinema = Application.Cinemas.Entities.Cinema;`, add `ICinemasRepository` to the interfaces the class implements, and add a `Cinemas` region. The search reuses the repository's own `ContainsPattern` and `EscapeCharacter`, so a `%` or `_` in a search term matches itself, the same as for movies.

     ```csharp
     #region Cinemas

     public async Task<Page<ApplicationCinema>> GetCinemas(
         string? query,
         PageRequest page,
         CancellationToken cancellationToken)
     {
         var cinemas = this.context.Cinemas.AsQueryable();

         if (!string.IsNullOrWhiteSpace(query))
         {
             var pattern = ContainsPattern(query);

             cinemas = cinemas.Where(c => EF.Functions.Like(c.Name, pattern, EscapeCharacter));
         }

         var totalCount = await cinemas.CountAsync(cancellationToken);

         var result = await cinemas
             .OrderBy(c => c.Name)
             .ThenBy(c => c.Id)
             .Skip(page.Offset)
             .Take(page.Limit)
             .ToListAsync(cancellationToken);

         return new([.. result.Select(this.mapper.ToDomain)], page.Offset, page.Limit, totalCount);
     }

     public async Task<ApplicationCinema> CreateCinema(string name, CancellationToken cancellationToken)
     {
         var now = this.timeProvider.GetUtcNow().UtcDateTime;

         var cinema = new Cinema
         {
             Name = name,
             DateCreated = now,
             DateModified = now
         };

         _ = this.context.Add(cinema);

         _ = await this.context.SaveChangesAsync(cancellationToken);

         return this.mapper.ToDomain(cinema);
     }

     #endregion Cinemas
     ```

   - **`src/Infrastructure/DependencyInjection.cs`:** add `using Application.Cinemas;` and register the interface against the same repository, like the others:

     ```csharp
     _ = services.AddScoped<ICinemasRepository>(x =>
         x.GetRequiredService<EntityFrameworkMovieReviewsRepository>());
     ```

4. **Put it on functions in `src/Presentation`** (`expose-a-use-case`, `api-conventions` and `json-serialization`).

   Every use case goes out twice, like the samples: a function you invoke directly with a request record, and an HTTP API function that API Gateway calls with the request in the path, query or body. Both share one private method, so the use case is only sent from one place.

   The function returns its own models, not the Application entities, so what goes over the wire is decided here.

   ```csharp title="src/Presentation/LambdaFunction/Models/Cinema.cs"

   /// A cinema that shows movies.
   /// </summary>
   /// <param name="Id">The unique identifier of the cinema.</param>
   /// <param name="Name">The name of the cinema.</param>
   public record Cinema(Guid Id, string Name);
   ```

   ```csharp title="src/Presentation/LambdaFunction/Models/CreateCinemaRequest.cs"
   namespace WorksOnMyMachine.Movies.Presentation.LambdaFunction.Models;

   /// <summary>
   /// Creates a cinema.
   /// </summary>

   {
       /// <summary>The name of the cinema, up to 100 characters.</summary>
   ```

   Then in `src/Presentation/LambdaFunction/`:

   - **`Mapping/LambdaFunctionMapper.cs`:** add `using AppCinema = Application.Cinemas.Entities.Cinema;` and `using PresentationCinema = Models.Cinema;` with the other aliases, and `public partial PresentationCinema ToPresentation(AppCinema cinema);`.
   - **`Serialization/LambdaFunctionJsonSerializerContext.cs`:** add `[JsonSerializable(typeof(CreateCinemaRequest))]`, `[JsonSerializable(typeof(Cinema))]` and `[JsonSerializable(typeof(Page<Cinema>))]`. Native AOT can't reflect, so a type that isn't listed here can't be read or written.
   - **`LambdaFunction.cs`:** add `using Application.Cinemas.Commands.CreateCinema;` and `using Application.Cinemas.Queries.GetCinemas;`, then the two functions and the methods they share:

     ```csharp
     /// <summary>
     /// Lists cinemas ordered by name, one page at a time, optionally only those whose name contains a search term.
     /// </summary>
     /// <param name="request">The search term, offset and limit.</param>
     /// <param name="context">The Lambda invocation context.</param>
     /// <returns>One page of cinemas.</returns>
     [LambdaFunction(ResourceName = "GetCinemas", PackageType = LambdaPackageType.Image, MemorySize = 256, Timeout = 30)]
     public async Task<Page<Cinema>> GetCinemas(ListRequest request, ILambdaContext context)
     {
         return await this.Invoke(request, context, () => this.ListCinemas(request, context));
     }

     /// <summary>
     /// Creates a cinema and returns it with its new id.
     /// </summary>
     /// <param name="request">The name of the cinema.</param>
     /// <param name="context">The Lambda invocation context.</param>
     /// <returns>The cinema that was created.</returns>
     [LambdaFunction(ResourceName = "CreateCinema", PackageType = LambdaPackageType.Image, MemorySize = 256, Timeout = 30)]
     public async Task<Cinema> CreateCinema(CreateCinemaRequest request, ILambdaContext context)
     {
         return await this.Invoke(request, context, () => this.AddCinema(request, context));
     }

     private async Task<Page<Cinema>> ListCinemas(ListRequest request, ILambdaContext context)
     {
         var page = await this.Send(new GetCinemasQuery
         {
             Query = request.Query,
             Offset = request.Offset,
             Limit = request.Limit
         }, context);

         return ToPage(page, this.mapper.ToPresentation);
     }

     private async Task<Cinema> AddCinema(CreateCinemaRequest request, ILambdaContext context)
     {
         return this.mapper.ToPresentation(await this.Send(new CreateCinemaCommand { Name = request.Name }, context));
     }
     ```

     And their HTTP API twins, beside the sample ones:

     ```csharp
     /// <summary>
     /// The same list as <see cref="GetCinemas"/>, for API Gateway: <c>GET /cinemas?query=&amp;offset=&amp;limit=</c>.
     /// </summary>
     /// <param name="query">The words to look for in the name, ignoring case. Leave empty to list every cinema.</param>
     /// <param name="offset">The number of cinemas to skip.</param>
     /// <param name="limit">The most cinemas to return, from 1 to 50.</param>
     /// <param name="context">The Lambda invocation context.</param>
     /// <returns><c>200</c> with one page of cinemas, or <c>400</c> with problem details when the request is invalid.</returns>
     [LambdaFunction(ResourceName = "HttpGetCinemas", PackageType = LambdaPackageType.Image, MemorySize = 256, Timeout = 30)]
     [HttpApi(LambdaHttpMethod.Get, "/cinemas")]
     public async Task<IHttpResult> HttpGetCinemas(
         [FromQuery] string query,
         [FromQuery] int? offset,
         [FromQuery] int? limit,
         ILambdaContext context)
     {
         var request = new ListRequest
         {
             Query = EmptyAsNull(query),
             Offset = offset ?? 0,
             Limit = limit ?? AppPaging.Paging.DefaultLimit
         };

         return await this.Invoke(request, context, () => Http(() => this.ListCinemas(request, context)));
     }

     /// <summary>
     /// The same as <see cref="CreateCinema"/>, for API Gateway: <c>POST /cinemas</c> with the name in the body.
     /// </summary>
     /// <param name="request">The name of the cinema.</param>
     /// <param name="context">The Lambda invocation context.</param>
     /// <returns><c>201</c> with the cinema, or <c>400</c> with problem details when the request is invalid.</returns>
     [LambdaFunction(ResourceName = "HttpCreateCinema", PackageType = LambdaPackageType.Image, MemorySize = 256, Timeout = 30)]
     [HttpApi(LambdaHttpMethod.Post, "/cinemas")]
     public async Task<IHttpResult> HttpCreateCinema([FromBody] CreateCinemaRequest request, ILambdaContext context)
     {
         return await this.Invoke(request, context, () => Http(() => this.AddCinema(request, context), HttpResults.Created));
     }
     ```

     A create should answer `201 Created`, and the `Http` helper only knew `200 OK`. Give it an optional `success` that turns the result into a response, so `HttpResults.Created` can take over, and update its summary to say so:

     ```csharp
     private static async Task<IHttpResult> Http<T>(Func<Task<T>> function, Func<string?, object?, IHttpResult>? success = null)
     {
         try
         {
             var result = await function();

             return success is null ? HttpResults.Ok(result) : success(null, result);
         }
         catch (ValidationException exception)
         ...
     ```

   The build regenerates `src/Presentation/serverless.template` from the attributes, so the four new functions show up there. Commit it with the code.

   The last table it prints is the merged total. Ours came out at 99.7%. If yours is under 95%, `coverage` says what to do about it, and it isn't "lower the number".

</Steps>

## What's still called "movie reviews"

The database plumbing keeps its sample name: the `Databases/MovieReviews` folder, `MovieReviewsDbContext`, `EntityFrameworkMovieReviewsRepository`, the `MovieReviews` connection string and the `movie-reviews.db` file. They all work as they are. Everything in `src/Infrastructure` is `internal`, so renaming them later is a refactor that never reaches Application or Presentation. Do it when the name starts to bother you, and change the connection string's name and `DefaultConnectionString` in `LambdaFunction/Startup.cs` at the same time.
