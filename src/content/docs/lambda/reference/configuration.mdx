## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `ConnectionStrings__MovieReviews` | `Data Source=/tmp/movie-reviews.db` | The SQLite connection string |
| `Database__SeedSampleData` | `false` | When `true`, seeds sample data into an empty database. Anything else, including no value, means no |
| `Serilog__MinimumLevel__Default` | `Information` | The minimum log level. Logs go to the console as compact JSON, which CloudWatch Logs keeps. `docker-compose.yml` sets it to `Debug` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | none | Where to send [OpenTelemetry](https://opentelemetry.io) traces, metrics and logs. Nothing is exported until it's set. Docker Compose sets it to the `otel-collector` service |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `grpc` | `grpc` or `http/protobuf` |
| `OTEL_EXPORTER_OTLP_HEADERS` | none | Headers for every export, such as an API key for a hosted backend |
| `OTEL_SERVICE_NAME` | `CleanLambdaFunction` | The `service.name` on everything sent. Every span, metric and log also carries `service.version`, the version stamped into the build |

## Docker Compose services

| Service | What it is | Port |
| --- | --- | --- |
| `function` | The image, built from the `run` stage, behind the runtime interface emulator | 8750 (8080 inside the container) |
| `otel-collector` | The [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/), configured by `otel-collector.yaml` | 8753 (gRPC), 8754 (HTTP) |
| `aspire-dashboard` | The [Aspire dashboard](https://learn.microsoft.com/dotnet/aspire/fundamentals/dashboard/standalone), where the collector sends everything | 8752 |

The ports are the ones on your machine. Each template has its own block of ten, so this one uses 8750 to 8759 and runs beside a solution made from any other template: Minimal API 8710, MCP 8720, GraphQL 8730, Web API 8740 and Lambda Function 8750. Inside their containers the services keep their usual ports.

## Docker build arguments

| Argument | Default | Description |
| --- | --- | --- |
| `VERSION_PREFIX` | `1.0.0.0` | The version stamped into the assemblies |
| `VERSION_SUFFIX` | none | A prerelease label added to the version |
| `ENVIRONMENT` | `docker` | Sets `DOTNET_ENVIRONMENT` during the build and tests |
| `BASE_IMAGE_REPO`, `BASE_IMAGE_BUILD`, `BASE_IMAGE_BUILD_TAG` | `mcr.microsoft.com`, `dotnet/sdk`, `10.0-alpine` | The SDK image used to build and test |
| `BASE_IMAGE_RUNTIME_REPO`, `BASE_IMAGE_RUNTIME`, `BASE_IMAGE_RUNTIME_TAG` | `public.ecr.aws`, `lambda/dotnet`, `10` | The Lambda base image the function runs on |

## Lambda deployment defaults

`src/Presentation/aws-lambda-tools-defaults.json` holds the defaults for `dotnet lambda deploy-serverless`.

| Setting | Default | Description |
| --- | --- | --- |
| `profile` | empty | Your AWS CLI profile |
| `region` | empty | The AWS region to deploy to |
| `configuration` | `Release` | The build configuration |
| `template` | `serverless.template` | The CloudFormation template to deploy |
| `stack-name` | empty | The CloudFormation stack the functions live in |

Each function's memory, timeout and package type are set on its `[LambdaFunction]` attribute, and the build copies them into `serverless.template`.

| Attribute property | Default | Description |
| --- | --- | --- |
| `MemorySize` | `256` | Memory in MB |
| `Timeout` | `30` | Timeout in seconds |
| `PackageType` | `Image` | Deploy as a container image |
