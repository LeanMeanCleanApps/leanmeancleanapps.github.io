```bash
dotnet new cleanlambdafunction --name <NAME> [--authorName|-an <AUTHOR>] [--output|-o <PATH>] [--no-restore]
```

`cleanlambda`, `lmca-lambda` and `leanmeancleanapps-lambda` are other names for the same template, so `dotnet new cleanlambda` takes the same options. `dotnet new search leanmeanclean` lists the whole family.

| Option | Default | What it changes |
| --- | --- | --- |
| `--name`, `-n` | The current folder's name | Replaces `CleanLambdaFunction` in every namespace, project, file and folder name, and names the output folder |
| `--authorName`, `-an` | `Stephen Walsh` | Sets the `Authors` and `Copyright` of the Presentation project, so the assembly credits you instead of us |
| `--output`, `-o` | A folder named after `--name` | Where the solution is created |
| `--no-restore` | off | Skips the package restore that otherwise runs as soon as the solution is created |

The usual `dotnet new` options such as `--dry-run` and `--force` work too. Run `dotnet new cleanlambdafunction --help` for the full list.

## In Visual Studio or Rider

Once the template is installed, it shows up in the new project dialog under its name, with the same options as labelled fields. Visual Studio restores the packages for you.

You'll need the .NET 10 SDK or later. Older SDKs get a polite note saying so instead of a half-made solution.

## Install, update and remove

| Task | Command |
| --- | --- |
| Install | `dotnet new install CleanLambdaFunction.Template` |
| Check for updates | `dotnet new update --check-only` |
| Update | `dotnet new update` |
| Remove | `dotnet new uninstall CleanLambdaFunction.Template` |

New versions are published on the 1st of each month when something has changed. See the [releases](https://github.com/LeanMeanCleanApps/CleanLambdaFunction/releases) for what's new.
