Sooner or later you'll want to evict *Deep Space Gardeners* and move your own domain in. The tempting move is to delete `Movies`, `Authors` and `Reviews` first. Don't. Half the tests stop compiling, and the shared plumbing (paging, validation, logging, the error filters, resource links, completions and telemetry) suddenly has nothing to exercise it, so coverage falls through the floor.

Go the other way round. Build your first slice beside the sample domain, prove it works end to end, then take the movies out. This guide adds cinemas, with a `cinemas_search` tool to list and search them, a `cinemas_add` tool to add one, a `cinemas://{id}` resource to read one and a `describe_cinema` prompt to write a blurb for one, and finishes with a solution that has no movies left in it. We ran every step on a fresh solution: it ends with 112 passing tests and 99.8% line coverage.

<Aside type="tip" title="Let Jacques do the typing">
  Each step names the skill in `.agents/skills/` that covers it. Point your coding agent at this page and your own domain, and it follows the same recipe.
</Aside>

The code below assumes you named the solution `WorksOnMyMachine.Movies`. Swap in your own name wherever you see it.

## Build the new slice

<Steps>

1. **Add the entity and use cases to `src/Application`** (`add-a-use-case`).

An MCP server needs the second query, `GetCinemaById`, more than an API does: every cinema a tool returns comes with a link to a `cinemas://{id}` resource, and something has to answer when a client opens it. Handlers and validators are `public`, like the samples, so Mediator's source generator and the tests can see them.

   Then wire it in:

   - **`MovieReviewsDbContext.cs`:** add `public DbSet<Cinema> Cinemas => this.Set<Cinema>();` beside the other sets.
   - **`Mapping/MovieReviewsMapper.cs`:** add `using AppCinema = Application.Cinemas.Entities.Cinema;` and `using InfraCinema = Models.Cinema;` with the other aliases, and this method:

     ```csharp
     [MapperIgnoreSource(nameof(InfraCinema.DateCreated))]
     [MapperIgnoreSource(nameof(InfraCinema.DateModified))]
     public partial AppCinema ToDomain(InfraCinema cinema);
     ```

   - **`EntityFrameworkMovieReviewsRepository.cs`:** add `using Application.Cinemas;` and `using ApplicationCinema = Application.Cinemas.Entities.Cinema;`, add `ICinemasRepository` to the interfaces the class implements, and add a `Cinemas` region. The search reuses the repository's own `ContainsPattern` and `EscapeCharacter`, so a `%` or `_` in a search term matches itself, the same as for movies.

     ```csharp
     #region Cinemas

     public async Task<Page<ApplicationCinema>> GetCinemas(
         string? query,
         PageRequest page,
         CancellationToken cancellationToken)
     {
         var cinemas = this.context.Cinemas.AsQueryable();

         if (!string.IsNullOrWhiteSpace(query))
         {
             var pattern = ContainsPattern(query);

             cinemas = cinemas.Where(c => EF.Functions.Like(c.Name, pattern, EscapeCharacter));
         }

         var totalCount = await cinemas.CountAsync(cancellationToken);

         var result = await cinemas
             .OrderBy(c => c.Name)
             .ThenBy(c => c.Id)
             .Skip(page.Offset)
             .Take(page.Limit)
             .ToListAsync(cancellationToken);

         return new([.. result.Select(this.mapper.ToDomain)], page.Offset, page.Limit, totalCount);
     }

     public async Task<ApplicationCinema?> GetCinemaById(Guid id, CancellationToken cancellationToken)
     {
         var result = await this.context.Cinemas.FirstOrDefaultAsync(c => c.Id == id, cancellationToken);

         return result is null ? null : this.mapper.ToDomain(result);
     }

     public async Task<ApplicationCinema> CreateCinema(string name, CancellationToken cancellationToken)
     {
         var now = this.timeProvider.GetUtcNow().UtcDateTime;

         var cinema = new Cinema
         {
             Name = name,
             DateCreated = now,
             DateModified = now
         };

         _ = this.context.Add(cinema);

         _ = await this.context.SaveChangesAsync(cancellationToken);

         return this.mapper.ToDomain(cinema);
     }

     #endregion Cinemas
     ```

   - **`src/Infrastructure/DependencyInjection.cs`:** add `using Application.Cinemas;` and register the interface against the same repository, like the others:

     ```csharp
     _ = services.AddScoped<ICinemasRepository>(x =>
         x.GetRequiredService<EntityFrameworkMovieReviewsRepository>());
     ```

   - **`Extensions/MovieReviewsDbContextExtensions.cs`** (`sample-data`): give `local` and `docker` some cinemas to look at. Add this to `AddData` before `SaveChanges`:

     ```csharp

         .RuleFor(c => c.Id, f => f.Random.Guid())
         .RuleFor(c => c.Name, f => $"{f.Address.City()} Picture House")
         .RuleFor(c => c.DateCreated, f => f.Date.Past(refDate: ReferenceDate))
         .RuleFor(c => c.DateModified, f => f.Date.Past(refDate: ReferenceDate))

     context.AddRange(cinemas);
     ```

   ```bash
   dotnet tool install --global dotnet-ef
   dotnet ef migrations add AddCinemas \
     --project ./src/Infrastructure \
     --output-dir Databases/MovieReviews/Migrations \
   ```

## Expose and test it

<Steps>

4. **Put it on tools, a resource and a prompt in `src/Presentation`** (`expose-a-use-case`, `api-conventions` and `json-serialization`).

   This is where an MCP server earns its keep. A model reads the tool names, titles, annotations and descriptions to decide what to call, so they're written for a model to read, the same way the sample's are. Tools return a result model rather than the Application entity, so the server decides exactly what a client sees.

   ```csharp title="src/Presentation/Models/CinemaResult.cs"
   namespace WorksOnMyMachine.Movies.Presentation.Models;

   using System.ComponentModel;

   /// <summary>
   /// A cinema that shows movies.
   /// </summary>
   /// <param name="Id">The cinema's id.</param>
   /// <param name="Name">The cinema's name.</param>
   public record CinemaResult(
       [property: Description("The cinema's id.")] Guid Id,
       [property: Description("The cinema's name.")] string Name);
   ```

   ```csharp title="src/Presentation/Tools/CinemaTools.cs"
   namespace WorksOnMyMachine.Movies.Presentation.Tools;

   using Mediator;
   using ModelContextProtocol.Server;
   using Presentation.Models;
   using Commands = Application.Cinemas.Commands;
   using Queries = Application.Cinemas.Queries;

   [McpServerToolType]
   public static partial class CinemaTools
   {
       /// <summary>
       /// Find cinemas by name, ignoring case, in name order. Each result has the cinema's id and name. Leave the query
       /// empty to browse every cinema a page at a time. Use this to check a cinema isn't already there before calling
       /// cinemas_add.
       /// </summary>
       /// <param name="query">Part of the cinema's name, such as 'astor'. Leave empty to list every cinema.</param>
       /// <param name="offset">The number of results to skip, 0 for the first page. Pass the nextOffset from a previous call to get the next page.</param>
       /// <param name="limit">The most results to return, from 1 to 50.</param>
       [McpServerTool(Name = "cinemas_search", Title = "Search cinemas", ReadOnly = true, Idempotent = true, OpenWorld = false, UseStructuredContent = true, IconSource = ItemIcons.Cinema)]
       public static async partial Task<ResultPage<CinemaResult>> SearchCinemas(
           ISender sender,
           CancellationToken cancellationToken,
           string? query = null,
           int offset = 0,
           int limit = 10)
       {
           var page = await sender.Send(new Queries.GetCinemas.GetCinemasQuery
           {
               Query = query,
               Offset = offset,
               Limit = limit
           }, cancellationToken);

           return page.ToResult(c => c.ToResult());
       }

       /// <summary>
       /// Add a cinema and return it with its new id. Calling it twice adds two cinemas, so search first with
       /// cinemas_search if you're not sure it's already there.
       /// </summary>
       /// <param name="name">The cinema's name, up to 100 characters, such as 'The Astor'.</param>
       [McpServerTool(Name = "cinemas_add", Title = "Add cinema", ReadOnly = false, Destructive = false, Idempotent = false, OpenWorld = false, UseStructuredContent = true, IconSource = ItemIcons.Cinema)]
       public static async partial Task<CinemaResult> AddCinema(
           ISender sender,
           string name,
           CancellationToken cancellationToken)
       {
           var cinema = await sender.Send(new Commands.CreateCinema.CreateCinemaCommand
           {
               Name = name
           }, cancellationToken);

           return cinema.ToResult();
       }
   }
   ```

   The annotations tell the client how careful to be. `cinemas_search` is read-only and safe to repeat. `cinemas_add` changes data, so it isn't read-only, but it doesn't destroy anything, and it isn't idempotent, because calling it twice adds two cinemas. The description says so, and points the model at `cinemas_search` first.

   Every cinema a tool returns gets a resource link to `cinemas://{id}`, because the scheme is the start of the tool's name. That link has to open, so add the resource:

   ```csharp title="src/Presentation/Resources/CinemaResources.cs"
   namespace WorksOnMyMachine.Movies.Presentation.Resources;

   using Mediator;
   using ModelContextProtocol.Server;
   using Presentation.Models;
   using Presentation.Serialization;
   using Presentation.Tools;
   using Queries = Application.Cinemas.Queries;

   [McpServerResourceType]
   public static partial class CinemaResources
   {
       /// <summary>A cinema, by its id.</summary>
       /// <param name="cinemaId">The cinema's id (a GUID).</param>
       [McpServerResource(UriTemplate = "cinemas://{cinemaId}", Name = "cinema", Title = "Cinema", MimeType = "application/json", IconSource = ItemIcons.Cinema)]

           CancellationToken cancellationToken)
       {

           {
               Id = cinemaId
           }, cancellationToken);

       }
   }
   ```

   And a prompt, so a client has something to offer the user for cinemas, not just the model:

## Take out the sample

<Steps>

6. **Take out the sample movies, authors and reviews** (`sample-data` and `database-migrations`).

   This step is mostly deleting, but the template's own tests use the sample as their test subject, so a few of them change instead of going. Work through it layer by layer and build as you go. The compiler finds what's left faster than any list.

   - **Application:** delete `src/Application/Authors/`, `Movies/` and `Reviews/`. In `Common/Enums/EntityType.cs`, remove `Author`, `Movie` and `Review`, which leaves `Cinema`.

## What's still called "movie reviews"

The database plumbing keeps its sample name: the `Databases/MovieReviews` folder, `MovieReviewsDbContext`, `EntityFrameworkMovieReviewsRepository`, the `MovieReviews` connection string and the `movie-reviews.db` file. They all work as they are. Everything in `src/Infrastructure` apart from `DependencyInjection` is `internal`, so renaming them later is a refactor that never reaches Application or Presentation. Do it when the name starts to bother you, and change the connection string in every `appsettings.*.json` and in `docker-compose.yml` at the same time.
