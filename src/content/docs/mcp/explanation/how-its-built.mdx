This page is about how we build the template itself. Your solution starts with a simpler pipeline, covered in [Set up CI](/mcp/guides/set-up-ci/), and you can borrow any of the checks below when you're ready.

These are templates we build for fun, but the pipeline doesn't know that. Every pull request goes through the same checks, and some of them are allowed to say no.

**Gatekeepers** fail the build and block the merge. **Tattletales** report what they find and leave the decision to a human.

## The rules on main

- Every change goes through a pull request, and every check above must pass.
- Only the maintainer can merge. Pull requests from anyone are welcome, but the green button has one owner.
- Commits must be signed, and merges are squashed so the history stays readable.
- Release tags can't be moved or deleted once they exist, so a version always means the same code.
- Third-party GitHub Actions are pinned to a commit, not a tag, so nobody can swap them out from under us.

## Releases

New versions go to [NuGet](https://www.nuget.org/packages/CleanModelContextProtocol.Template) on the 1st of each month, but only when something outside the `.github` folder has changed. Publishing uses NuGet [trusted publishing](https://learn.microsoft.com/nuget/nuget-org/trusted-publishing), so there's no long-lived API key sitting in the repository waiting to leak. Each release gets a [GitHub release](https://github.com/LeanMeanCleanApps/CleanModelContextProtocol/releases) with generated notes and an SPDX bill of materials.
