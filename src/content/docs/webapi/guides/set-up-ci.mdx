Whichever way you made your solution, it starts with a simple pipeline: format, build, and test with a 95% coverage bar. Those are the same commands as in `AGENTS.md`, so the pipeline and your laptop agree on what "green" means. It needs no secrets, no accounts and no paid features. Everything else is yours to add when you want it.

## Made with `dotnet new`

You get `.github/workflows/ci.yml`, one GitHub Actions job that restores, checks formatting, builds, runs every test and checks the coverage total. Push to GitHub and it runs.

Not on GitHub Actions? Ask your coding agent to move it. It works as Jacques, so it uses the `ci-for-your-solution` skill in `.agents/skills` to port the same commands to Azure Pipelines, GitLab, or the Jenkins box under someone's desk, then breaks something on purpose to prove the new pipeline notices.

## Made with "Use this template"

Your copy has our Build Pipeline. Outside the LeanMeanCleanApps organisation it runs the format check, build and tests, and the Summary shows the rest as not run. That covers CodeQL, Dependency Review, the container scan, and the steps that pack, verify and publish the template. So a private copy goes green without GitHub Advanced Security, and it never tries to publish to NuGet on your behalf.

### After you copy

<Steps>

1. Change `.github/CODEOWNERS` from `@stphnwlsh` to your own team. Otherwise GitHub has nobody to ask for reviews.

2. Make the checks required on `main` with a branch ruleset: Build, Test and Summary.

3. Fill in **Where we track work** in `AGENTS.md`, so agents put their plans and handoffs where your team will see them.

</Steps>

## Adding more

The `ci-for-your-solution` skill lists the checks you can add, what each one catches and what it needs, from a vulnerable package check that needs nothing to CodeQL, which needs Advanced Security on a private repository. Ask your agent to add one and it will agree it with you first.

For a worked example of every check, read our [Build Pipeline](https://github.com/LeanMeanCleanApps/CleanWebApi/blob/main/.github/workflows/build-pipeline.yml). Borrow freely, but leave out the jobs that pack and publish the template. You're shipping an app, not a template.
