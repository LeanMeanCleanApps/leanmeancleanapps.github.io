There are two ready-made environments. `local` is for `dotnet run`: sample data on, logs to the console. `docker` is for Docker Compose: sample data on, logs, traces and metrics to the Aspire dashboard, database on a volume. Both are for your machine. Neither is for production, which is why neither is the default.

## Run it

<Tabs syncKey="runner">
  <TabItem label="dotnet run">
    ```bash
    dotnet run --project ./src/Presentation
    ```

    `launchSettings.json` sets the environment to `local` and listens on [https://localhost:7341](https://localhost:7341), and on `http://localhost:7340`, which redirects to it. If your browser or `curl` doesn't trust the .NET development certificate yet, run `dotnet dev-certs https --trust` once.
  </TabItem>
  <TabItem label="Docker Compose">
    ```bash
    docker compose up -d --build
    ```

    Compose builds the `run` stage, starts an OpenTelemetry Collector and the Aspire dashboard next to it, and publishes the API on [http://localhost:7340](http://localhost:7340). Shut it down with `docker compose down`, or `docker compose down -v` to drop the database too.
  </TabItem>
  <TabItem label="Docker">
    ```bash
    docker build . --target run --tag acme-movies:local
    docker run --rm -p 7340:7340 -e DOTNET_ENVIRONMENT=docker acme-movies:local
    ```

    Without Compose there's no collector, so the logs stay on the console and nothing else is exported. Set `OTEL_EXPORTER_OTLP_ENDPOINT` to send them to a collector of your own.
  </TabItem>
</Tabs>

## Find your way around

| Where | What |
| --- | --- |
| `/scalar` | The Scalar API reference, built from the OpenAPI document |
| `/openapi/v1.json` | The OpenAPI document itself |
| `/health/live` | Answers 200 while the process is up |
| `/health/ready` | Answers 200 when the database can be reached |
| `/api/version` | The version stamped into the build. Needs a token when authentication is on |
| [http://localhost:7342](http://localhost:7342) | The Aspire dashboard, with the logs, traces and metrics, when running with Docker Compose |

The health endpoints answer without a token even when authentication is on, so a load balancer never needs to log in.

## See the telemetry

Docker Compose runs an [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/) beside the API, and the collector forwards everything to the [Aspire dashboard](https://learn.microsoft.com/dotnet/aspire/fundamentals/dashboard/standalone) at [http://localhost:7342](http://localhost:7342). Open **Traces** to follow a request from the HTTP request to the use case, **Structured** for the logs, each linked to its trace, and **Metrics** for request durations, EF Core queries and the runtime. The dashboard keeps everything in memory, so it's empty again after a restart. The dashboard has no login, and the collector accepts OTLP from anyone on ports 7343 and 7344. That's on purpose, so there's nothing to sign in to on your machine, and it's why the compose file is for your machine only. Don't run it anywhere other people can reach.

The API only ever talks OTLP to the collector, and `otel-collector.yaml` decides where things go. To send them to a real backend, add its exporter there; the API doesn't change. To see a `dotnet run` in the dashboard, start the collector and point the API at it:

```bash
docker compose up -d otel-collector
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:7343 dotnet run --project ./src/Presentation
```

## Try the endpoints

Open `src/Presentation/Presentation.http` in Visual Studio, Rider or VS Code to run a request for every endpoint in one click, or call them from the terminal. These use the `dotnet run` address; with Docker Compose, use `http://localhost:7340` instead. The sample data uses a fixed seed, so these ids are the same on every machine. See the [endpoint reference](/webapi/reference/endpoints/) for every parameter and response.

```bash
# Search movies, two at a time
curl "https://localhost:7341/api/movies?query=space&limit=2"

# One movie, with its reviews
curl "https://localhost:7341/api/movies/cb188ef6-14e7-f85f-2f78-924c2ab26b28"

# Write a review
curl -X POST "https://localhost:7341/api/reviews" -H "Content-Type: application/json" \
  -d '{"authorId":"01fa8b58-05d2-abd4-e55c-2633222dd0a5","movieId":"cb188ef6-14e7-f85f-2f78-924c2ab26b28","stars":5,"text":"Great film. I cried at the ending."}'
```

## Run the tests

```bash
dotnet test
```

Each test class builds its own in-memory SQLite database from the migrations and the same fixed seed. No test can change what another one sees, and nothing touches `movie-reviews.db`.

## Run just one part of the Dockerfile

The `Dockerfile` has a stage for each job, so you can build only what you need.

| Stage | What it does |
| --- | --- |
| `build` | Restores and builds the solution |
| `test` | Runs every test with coverage |
| `coverage` | Exports the coverage report to your machine |
| `publish` | Publishes the Presentation project |
| `run` | The image you deploy |

```bash
docker build . --target coverage --output type=local,dest=out
```

## Stamp a version

```bash
docker build . --target run --tag acme-movies:latest \
  --build-arg VERSION_PREFIX=1.2.3 --build-arg VERSION_SUFFIX=beta
```

`GET /api/version` then reports `1.2.3-beta` and the commit it was built from.

<Aside type="tip" title="Stuck?">
  If the first request takes a moment, the API is applying migrations and seeding. If `curl` says connection refused, check that ports 7340 and 7341 aren't busy with something else you forgot about.
</Aside>
