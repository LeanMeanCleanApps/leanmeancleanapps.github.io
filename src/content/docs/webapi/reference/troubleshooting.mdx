The template is set up to work out of the box, which mostly means the things that go wrong are environmental: a port already taken, a certificate the browser hasn't met yet, or Docker taking a nap.

## Port 7340 or 7341 is already in use

**Symptom:** `dotnet run` stops with `Failed to bind to address https://127.0.0.1:7341: address already in use`, or `docker compose up` fails with `Bind for 0.0.0.0:7340 failed: port is already allocated`.

Each Lean Mean Clean template has its own block of ten ports so different templates don't step on each other. Clean Web API uses `7340` to `7349` (`7340` HTTP, `7341` HTTPS, `7342` Aspire dashboard, `7343` and `7344` OpenTelemetry Collector). A clash usually means another copy of this template is still running.

- Check what's running in Docker and stop it:
  ```bash
  docker compose ps
  docker compose down
  ```
- Find a stray host process holding the port (`lsof -i :7340` on macOS and Linux, `netstat -ano | findstr :7340` on Windows) and stop it.
- To move a Docker port, change the left-hand side of its mapping in `docker-compose.yml` (for example `"7345:7340"`) and check the mapped port with:
  ```bash
  docker compose port api 7340
  ```
- To move the `dotnet run` ports, edit `applicationUrl` in `src/Presentation/Properties/launchSettings.json`.

## Browser certificate warning or empty `curl` reply on `dotnet run`

**Symptom:** Your browser warns that `https://localhost:7341` is untrusted, `curl` fails with `SSL certificate problem: unable to get local issuer certificate`, or calling `http://localhost:7340` returns `307 Temporary Redirect` with an empty body.

In the `local` environment (`dotnet run --project ./src/Presentation`), Kestrel listens on both `http://localhost:7340` and `https://localhost:7341` and redirects HTTP to HTTPS.

- Trust the .NET development certificate once on your machine, then restart your browser:
  ```bash
  dotnet dev-certs https --trust
  ```
- Call `https://localhost:7341` directly when using `dotnet run`, or pass `-L` to `curl` so it follows the redirect.
- Under `docker compose up -d --build`, the container runs in the `docker` environment and serves plain HTTP on `http://localhost:7340` with no redirect and no certificate needed.

## `.NET SDK` version refused by `dotnet new` or `global.json`

**Symptom:** `dotnet new cleanwebapi` refuses to run because the SDK constraint `[10.0.100,)` isn't met, or `dotnet build` fails with `NETSDK1141` / `A compatible .NET SDK was not found`.

Both `.template.config/template.json` and the generated `global.json` require a stable .NET 10 SDK (`10.0.100` or newer, rolling forward to the latest feature band with `allowPrerelease: false`).

- Check which SDKs are installed:
  ```bash
  dotnet --list-sdks
  ```
- Install the current stable [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0). If you only have a preview SDK installed on the machine, either install the stable SDK alongside it or set `"allowPrerelease": true` in `global.json`.

## `--include-auth` fails with exit code 102

**Symptom:** Running `dotnet new cleanwebapi --include-auth` stops before writing any files and exits with code `102` (`Invalid option(s)` / missing mandatory option `--authority`).

When `--include-auth` is switched on, `--authority` is required so a generated solution never starts with a blank JWT issuer. Pass the authority (and optionally `--audience`) alongside `--include-auth`:

```bash
dotnet new cleanwebapi --name WorksOnMyMachine.Movies \
  --include-auth \
  --authority "https://your-tenant.example.com" \
  --audience "https://api.example.com"
```

See [Secure the API](/webapi/guides/secure-the-api/) for configuring tokens after generation.

## Docker is not running

**Symptom:** `docker compose up -d --build` fails with `Cannot connect to the Docker daemon` or `error during connect`.

Start Docker Desktop (or the Docker service on Linux) and wait for `docker info` to return cleanly before running `docker compose up -d --build`. You don't need Docker for `dotnet build`, `dotnet test` or `dotnet run --project ./src/Presentation`; the integration tests run against an in-memory SQLite database.

## `SQLite Error 5: 'database is locked'`

**Symptom:** Startup migration or a write request fails with `Microsoft.Data.Sqlite.SqliteException (0x80004005): SQLite Error 5: 'database is locked'`.

`dotnet run` writes to `src/Presentation/movie-reviews.db`. A lock means another process is holding an open write transaction against that file — usually a second `dotnet run` terminal or a database viewer.

- Stop the other process holding `src/Presentation/movie-reviews.db`.
- If you want to wipe the local database and re-seed the sample data from scratch, stop the API, delete `src/Presentation/movie-reviews.db` (and any `-shm` or `-wal` files beside it), and start the API again.
- In Docker Compose, `docker compose down -v` removes the `movie-reviews-data` volume so the next `docker compose up -d` starts with a fresh database.

## Scalar or `Presentation.http` returns `401 Unauthorized`

**Symptom:** Requests return `401 Unauthorized` when the solution was created with `--include-auth`.

Every `/api/*` controller action requires a valid JWT bearer token when authentication is included.

- In Scalar (`/scalar`), click **Authorize** at the top of the page and paste a bearer token issued by your `--authority`.
- In `src/Presentation/Presentation.http`, paste your token into the `@token =` variable at the top of the file before sending requests.
