## Two commands and you're in business

```bash
dotnet new install CleanMinimalApi.Template
dotnet new cleanminimalapi --name Acme.Movies --authorName "Your Name"
```

That's a solution with three layers, four test projects, a Dockerfile and a CI pipeline. Now go and tell your team you've been working on it all week.

## What's in the box

<CardGrid>
  <Card title="Endpoints, not boilerplate" icon="puzzle">
    Minimal API endpoints grouped by feature. Each one sends a command or query through Mediator and gets out of the way.
  </Card>
  <Card title="Docs that write themselves" icon="document">
    OpenAPI comes from the XML comments you were going to write anyway, and Scalar turns it into an API reference you can actually click around in.
  </Card>
  <Card title="Errors with manners" icon="warning">
    Validation lives in the Application layer with FluentValidation, and every failure comes back as Problem Details (RFC 9457). No mystery 500s.
  </Card>
  <Card title="Tested like it matters" icon="approve-check">
    xUnit, Shouldly and a 95% coverage gate. Every test gets its own throwaway SQLite database, so nobody steps on anybody's toes.
  </Card>
</CardGrid>

## Run it

```bash
cd Acme.Movies
docker compose up -d
```

Then open the Scalar API reference at [http://localhost:8080/scalar](http://localhost:8080/scalar) and start poking. The logs go to Seq at [http://localhost:5341](http://localhost:5341), because `Console.WriteLine` is not an observability strategy.

Want it locked down? Pass `--authority` and `--audience` when you create the solution and every movie, author and review endpoint needs a JWT bearer token. Leave them off and it runs wide open, which is lovely on a laptop and less lovely in production.

Clean Minimal API is one of five [Lean Mean Clean Apps](/) templates. They share the same Application and Infrastructure layers, the same tests and the same pipeline. Only Presentation changes. Like a family, really. Same genes, different haircuts.
