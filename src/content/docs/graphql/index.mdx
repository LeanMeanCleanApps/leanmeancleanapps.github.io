## Two commands and you're in business

```bash
dotnet new install CleanGraphQLApi.Template
dotnet new cleangraphqlapi --name Acme.Movies --authorName "Your Name"
```

That's a solution with three layers, three test projects, a Dockerfile and a CI pipeline. Now go and tell your team you've been working on it all week.

## What's in the box

<CardGrid>
  <Card title="Hot Chocolate, served hot" icon="puzzle">
    A source-generated Hot Chocolate schema with the Nitro IDE built in, and descriptions pulled from the XML comments on your models.
  </Card>
  <Card title="Paging done properly" icon="magnifier">
    Relay-style cursor paging and search on movies, authors and reviews, with a DataLoader so a page of 50 movies takes three queries, not 52.
  </Card>
  <Card title="Errors with manners" icon="warning">
    Validation lives in the Application layer with FluentValidation, and failures come back as GraphQL errors with proper codes in the extensions.
  </Card>
  <Card title="Tested like it matters" icon="approve-check">
    xUnit, Shouldly, a schema snapshot test and a 95% coverage gate. Every test gets its own throwaway SQLite database.
  </Card>
</CardGrid>

## Run it

```bash
cd Acme.Movies
docker compose up -d
```

Then open Nitro, the GraphQL IDE, at [http://localhost:8080/graphql](http://localhost:8080/graphql) and start querying. The logs go to Seq at [http://localhost:5341](http://localhost:5341), because `Console.WriteLine` is not an observability strategy.

Want it locked down? Pass `--authority` and `--audience` when you create the solution and the movie, author and review queries and the review mutations need a JWT bearer token. Leave them off and it runs wide open, which is lovely on a laptop and less lovely in production.
